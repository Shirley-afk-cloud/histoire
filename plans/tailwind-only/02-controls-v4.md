# 02 — `@histoire/controls` on Tailwind v4

## Outcome and prerequisites

Depends on: 01. `@histoire/controls` builds standalone and peer CSS with Tailwind v4, prefix `htw`. Visual output unchanged. Coexistence with story Tailwind proven on v4 output before the app follows.

## Owned files

- `packages/histoire-controls/package.json` (deps, `build:css`, `build:peer:css`).
- `postcss.config.cjs`, `postcss.peer.config.cjs`; delete `tailwind.config.cjs`, `tailwind.peer.config.cjs` once replaced (check `histoire-controls-stories/tailwind.config.cjs`, which requires `@histoire/controls/tailwind.config.cjs`: give it its own v3 config or migrate it, see step 6).
- `src/style/main.css`, `src/style/peer.css`, new `src/style/theme.css` (and generated peer theme, step 3).
- `src/style/controls.pcss` (only `htw-range-input` and any `htw-` class names it defines).
- The 14 `.vue` files using `htw-` utilities: prefix rewrite only.
- `src/style/tailwind-defaults.spec.ts`.
- `scripts/peer-style.mjs` if output file names change.

## Tests first

1. Port `tailwind-defaults.spec.ts` to v4: compile `theme.css`/entry with `@tailwindcss/postcss` (or `compile` from `tailwindcss`) against a raw candidate list built at runtime (keep the trick that avoids literal class names), assert no rule outside `.htw\:` selectors sets `--tw-*` (covers v4's `@supports` fallback `*` block), and that prefixed utilities still get their defaults (via `@property` or inline). Run for controls and, from slice 03 on, for the app entry.
2. Existing consumer spec `histoire/src/node/__tests__/embed/consumers/packages.spec.ts` keeps finding the published CSS files.

## Implementation steps

1. Add package-local `tailwindcss@^4.3`, `@tailwindcss/postcss`, `@tailwindcss/cli`; drop `postcss-import`, `autoprefixer`, `tailwindcss/nesting` from both PostCSS configs. Keep the peer `histoire-peer-root` scope plugin.
2. Entry CSS: `@import "tailwindcss/theme.css" layer(theme) prefix(htw)` + `utilities.css` with same prefix; no preflight; `@source "../"`. Port root-config theme bits controls use (radius overrides, `!sm` screens to `max-*`, cursor and transition extensions only if used).
3. Colors: today the peer config builds function colors with fallbacks from `@histoire/protocol` (`getHistoireColorChannels(parseColor(...))`). v4 has no function colors. Generate `src/style/peer-theme.css` with a small script (checked in, regenerated by a `generate:peer-theme` script) emitting `--color-<name>-<shade>: rgb(var(--_histoire-color-<name>-<shade>, <channels>) / var(--_histoire-color-<name>-<shade>-alpha, <alpha>))`. Standalone build uses the same variables without fallback, matching today.
4. Rewrite classes `htw-<utility>` → `htw:<utility>`, variants `dark:htw-x` → `htw:dark:x`, `hover:htw-x` → `htw:hover:x`, `!sm:htw-x` → `htw:max-sm:x`. Use `npx @tailwindcss/upgrade` as a starting point on a copy, then review by hand; it does not know the custom color functions.
5. Dark variant: `@custom-variant dark` matching `.htw-dark` and `[data-histoire-appearance="dark"]` (same as app, [architecture](architecture.md#entry-stylesheet)).
6. `histoire-controls-stories`: stays on root v3 config with its own copy of the old controls config, or moves to v4 with the controls theme; pick the smaller diff and record it.
7. Coexistence spike: build an `examples/nuxt-ui` (Tailwind 4) and `examples/vue3` (Tailwind 3) book with the new controls CSS; compare against slice 01 coexistence screenshots. Check `@property` duplicates, `--tw-*` collisions, layer ordering between controls utilities and story utilities. Record findings in [architecture.md](architecture.md#coexistence-with-story-tailwind) and any needed mitigation (PostCSS step dropping the fallback block) here.

## API changes

None public. Published CSS file names unchanged. Class names in published components change prefix form (`htw:`); consumers styling those internals were never supported.

## Failure paths

- v4 output larger than v3 by >10%: inspect for unscanned-but-emitted theme variables (`@theme` emits only used variables by default; `static` option not used).
- Browser support: v4 needs Safari 16.4+, Chrome 111+, Firefox 128+. Record in docs if Histoire documented older support.

## Validation commands

~~~bash
pnpm --filter @histoire/controls build
pnpm --filter @histoire/controls test
pnpm --filter @histoire/app build
pnpm --filter histoire test:embed:consumers
~~~

Browser: controls standalone stories (`histoire-controls-stories`) light/dark against baseline.

The app (still v3) scans controls source for utilities. Once controls classes use `htw:`, the v3 app scan no longer emits them, so the app shows unstyled controls until slice 03 lands. Run 02 and 03 back to back and validate the app only after 03; never hand off a tree between them.

## Acceptance criteria

Controls on v4, defaults guard green, coexistence documented, no visual diff in controls stories. App-side controls checked in slice 03.

## Non-goals

Migrating controls `<style>` blocks (7 files) or `controls.pcss` to utilities.

## Status

Implemented 2026-10-25, uncommitted; validated jointly with slice 03.

Landed:

- Package-local v4 PostCSS compilation, `htw:` utility prefixes in all 14 Vue
  files, shared `base-theme.css`, generated channel themes, dual dark selector,
  unchanged standalone/peer CSS output names. No controls component style block
  converted. Existing `htw-range-input` and `htw-bind-col-size` markers remain.
- `generate:peer-theme` emits both checked-in theme files from root v3 palette
  and protocol color parsing. Peer scoping maps theme roots onto the provider.
- Shared `scripts/build-tailwind.mjs` builds with actual PostCSS chains and
  supports watches; peer CSS composition now happens on each build/watch, so
  obsolete `scripts/peer-style.mjs` is removed. Old Tailwind configs removed.
- Defaults guard compiles actual standalone, peer and app entries; added theme
  coverage and external v3-consumer compatibility coverage. Fault probes remove isolation and
  surface mapping in memory and demonstrate the intended assertions failing.

Deviations:

- V4 CLI no longer supports `--postcss`. A shared PostCSS runner is required to
  preserve peer/app scoping and identical Vite/standalone processing; no extra
  package or dependency install needed.
- Old standalone config used literal colors, not channel variables. It uses
  generated canonical fallbacks like peer controls, preserving use without a
  themed host. App theme remains without palette fallbacks.
- Controls stories retain root v3 with local config, and import built standalone
  CSS instead of feeding the v4 source entry to root v3. No standalone-controls
  baseline screenshots were supplied; build/browser boundaries recorded below.
- `HstColorShades.story.vue` exceeded 300 lines because it duplicated Node
  `defaultColors`. Exact deep equality verified, then replaced that duplicate
  with the existing portable data import; file is now below 300 lines.
  Story fixtures are excluded from controls declaration emission so they do
  not pull that example-only import outside the library `rootDir`.
- Shared compiler helpers and controls-stories setup are added to owned scope
  in inventory drift. No existing app/component CSS was migrated in this slice.

Exceptions: E12 drops v4's universal fallback reset layer. Native global
`@property` defaults remain; supported browsers need v4's published baseline.
